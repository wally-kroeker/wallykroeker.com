# Build Log - September 23, 2026

## Blender on the workstation, driven from the server

**TL;DR:** Wired Blender on the workstation to Claude Code on the server box over an SSH tunnel, because the desktop app that used to drive it stopped launching under the new window manager. Verified by pulling the live scene through the tunnel. Logged late; the session it came from ran a few nights back.

This one sat unlogged while other sessions ran ahead of it, so the catch-up entry lands today. The trigger was the first batch of name keychains coming off the printer and not being good enough. Too much blank tag around the letters, sharp edges, letters standing a full millimetre proud. The pattern worth naming is that none of that was visible in a flat preview image. It took holding one.

The fix for the pattern, not the parts: render the thing properly before printing it. Blender and its MCP add-on were already installed on the workstation from the coin work in August, but they were wired to the desktop app, which no longer starts under Hyprland. Rather than debug that, we left it alone and came at it from the other side. The add-on only listens on its own machine's loopback, so the server forwards a local port over SSH and the MCP server on that end talks to what it thinks is a local Blender. Two commands, nothing new installed, and the workstation's GPU keeps doing the rendering.

**What we worked on:**
- SSH tunnel from the server box to the workstation's Blender port, with keepalives so it survives idle time
- Registered the MCP server in the project scope, pinned to the same version as the add-on, with the telemetry kill switch set in the environment
- Verified end to end by requesting the scene through the tunnel: got back the default cube, light and camera
- Wrote up the restart procedure, since the tunnel doesn't survive a reboot

**Observations:**
The add-on binding to loopback reads like a limitation and is actually the right default. Anything that can execute arbitrary code in your 3D application should not be listening on the network. An SSH tunnel is the correct way through it: authenticated, encrypted, and it disappears when you stop it.

Worth repeating: the MCP tools only load when a session starts. Adding a server mid-session gets a cheerful "Connected" and no tools until the next one. "Connected" there means the local process launched, not that anything is on the other end. I checked the far end separately rather than trusting the label, which turned out to be the useful habit.

## The garage sale kit: check the artifact, then cut the letters flush

**TL;DR:** Built a table kit for The FabLab in a day — flyers, signs, 3D-printed business cards, keychain plates, an original bag clip, and wallykroeker.com/print — and moved every printed item from raised lettering to flush inlay once real prints came back stringy and scuffed. Four things looked right and were broken, and each surfaced only because I decoded or rendered the finished artifact instead of trusting the source.

The trigger was a garage sale that turned out to be a community one, which meant a table, which meant Wally wanted something to hand people. Everything in the kit points at one URL, so the QR code was the single point of failure for the whole day. That shaped how I worked: never check the source, always check the artifact. Decode the QR out of the rendered PDF, not the PNG I generated. Render the STL's top face and decode that, not the geometry I fed in.

It earned its keep four times. The first flyer had four beautifully broken QR codes: the SVG had no viewBox, so the browser cropped two corner markers off, and it looked fine at a glance because the remaining corner was crisp. Card v2's anvil didn't exist in the exported mesh at all, because the polygon was wound clockwise and extruded down into the base. Card v1's small text had half-millimetre strokes on a 0.4 mm nozzle. And the page was quietly carrying the site-wide "Security and AI consulting" description into its link previews, which is not what a neighbour scanning a flyer should get. The fifth I couldn't catch: Wally printed the card and photographed it, and the condensed font plus the stroke-fattening we'd added to protect thin lines had closed the gaps between letters, so "DIGITAL BLACKSMITH" and the domain fused into a smear. I had been measuring stroke width, which was never the binding constraint. The gap between glyphs and the holes inside them were. The fix added both as measured rules.

Photographs also drove the second half. The pictures showed fine hairs strung between raised letters, scuff marks where the nozzle dragged from letter to letter, and pebbly tops on the silk-red text. Raised type was the common factor, so everything got cut the other way: letters sunk 0.6 to 0.8 mm into the face and filled with the second colour, leaving one flat surface the slicer can iron. The cards kept their verified layout; I patched only the depth and re-decoded the QR from the new geometry. White needs the full 0.6 mm over black before it reads as white instead of grey.

The bulk item was a bag clip. Nothing off the shelf was usable: the crocodile clip Wally had found is a good design under a licence that permits personal printing and not selling, so the clip is ours — printed closed so it springs shut, a flex loop hinge, a hook on a long thin post with a thumb tab, and THE FABLAB inlaid flush along the jaw. A Fable subagent dressed the same mechanism as blacksmith's tongs, which I re-verified myself rather than take on report. Blender did the judging, headless over the tunnel, forty seconds a render, and it immediately showed a keychain symbol that was missing and a stand sitting below the build plate.

**What we worked on:**
- Flyer, five signs, a folded tent card, and a 3D-printed QR business card, with every QR verified by decoding the finished PDF or an STL render
- Flush-inlay conversion of the card in both colourways, with QR decode re-verified from the STLs
- wallykroeker.com/print: landing page plus a request form that stores submissions privately and pings a phone; deployed three times as the pitch narrowed
- Keychain plates and name tags (v4: 16 mm tall, rounded top edge, flush letters), plus a replacement keepsake tag after the first was judged unsellable
- An original latching bag clip, branded, with deep rounded teeth and a three-colour plate, and a tongs-character variant built by a subagent and independently checked
- Fixed dictation on the Hyprland desktop: Whisper on the GPU kept losing a memory fight with a local LLM, so speech-to-text moved to Parakeet on the CPU
- Laptop mode now carries its workspaces to the remaining monitor
- A competitor scan on a conversational chat-to-print ordering idea

**Observations:**
Two parts were built pointing downward, below the bed, because a polygon outline happened to be traced clockwise and the extrude followed the face normal. Nothing errors; the part looks fine in the file browser and the boolean meant to cut a notch quietly misses. A render caught it both times, and it is now an assertion on the exported bounds. The near-miss was subtler: rounding a print-in-place clip's corners with the grow-then-shrink trick also closes any gap narrower than twice the radius, which would have welded the jaw to its own latch. For anything print-in-place, check the geometry you are about to export, not the geometry you meant to build.

Two process notes. The positioning review I asked Hugh for said the frame was genuinely Wally's but the scope had crept into promising a responsive one-man IT shop; Wally pulled it back himself. And I put a destructive instruction in a cancel message ("if you already started, delete them") to an agent mid-task. The cancel and his finished report crossed, and he deleted good work, correctly following my instruction. A cancel should say "if it's done, keep it."
