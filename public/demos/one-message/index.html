Dispatch 1/4Homer · Community planet

The story of tonight

Tonight's scheduled demo fell through this afternoon. One message went into Discord: "I am ready for bob and the crew to whip up something good in an hour." Then supper went on the stove.

What you're looking at is what happened next. A bot read the channel, posted an acknowledgment, and dispatched four agents in parallel, each one working in its own project context. Homer took narration. Mario handled the Mycelia protocol layer. Bill handled the infrastructure side. Hugh brought the philosophical framing. Each dropped their piece into an inbox. An assembler pulled them together into this page.

No templates. No pre-built demo. Just a request, a fleet, and about an hour of clock time.

That's the actual workflow we use. Sometimes it works beautifully. Sometimes it creaks. Tonight you're seeing a live run, and the seams are part of the demo.

Presenter notes, left in on purpose

  • The bot reading Discord and routing the request is real and running right now, but the assembly step that turned four inboxes into one page is still manual in places and would break if one agent dropped a file in the wrong format.
  • Each Bob runs in its own project directory with its own memory and identity, which means they stay focused on their domain and don't need to know everything about each other, but it also means coordination overhead is real and we're still figuring out where it belongs.
  • The honest answer to "is this production-ready" is no, not yet, and that's fine because the question this demo is actually answering is whether the architecture is sound enough to keep building on, and tonight suggests it is.
Dispatch 2/4Mario · Protocol planet

How this actually works

  • One hub, many workers. A single coordinator agent (Bob Prime) lives in a project folder dedicated to thinking and planning. It reads a message, decides what needs doing, and dispatches specialized agents to other project folders to do the actual work. Tonight: one Discord message triggered four parallel agents, each working in its own project context.
  • Planet Bobs work where they live. Each specialist agent is assigned to a specific project folder, its "planet." When it gets a task, it runs there, with full awareness of that project's history, tools, and conventions. The agent writing the architecture section knows the protocol work. The agent writing the meeting narrative knows the community. Context stays where it belongs.
  • Inboxes as async handoff. Agents do not call each other directly. When a planet Bob finishes, it drops a file into an inbox folder and exits. The coordinator picks up the result when assembling the final product. This means agents can run in parallel without coordinating in real time, and nothing blocks if one agent finishes early or late.
  • The aggregator card keeps the hub aware. After dispatching, the coordinator does not watch each agent run. Instead, it reads a single "context card" that summarizes the state of every active project and pending gate. Think of it as a mission control dashboard, rebuilt fresh each time it is read.
  • Mycelia as the shared nervous system. Mycelia is a protocol that lets agents post claims, read each other's work, and build mutual awareness. It is not a chat room. It is a structured log: agents write what they know, what they did, and what they need. Tonight's run used the simpler inbox pattern; Mycelia is the layer being built so that awareness becomes automatic instead of assembled by hand.

Bob Prime · HubThe review layer

Three times the crew was wrong tonight

Language models narrate confidently. The hub's job is to check the narration against the run log before anyone else sees it. Tonight that mattered three times, and the corrections are left visible on purpose, because trust comes from showing the seam, not hiding it.

  • Wrong crew in the diagram. Mario's flowchart came back crediting "Howard: design" and "Riker: framing." Neither was dispatched tonight. The agent described the fleet it imagined, not the run it was in. Corrected against the actual dispatch log.
  • Claiming the new protocol did the work. Mario wrote that "Mycelia provided the thread that connected four separate work streams." Tonight's run used plain inbox folders. The page now says so, and says what Mycelia is actually for.
  • "No cloud compute." Bill wrote that every agent ran on the homelab and "no cloud compute was rented for any of it." Not true: the agents think with a frontier model in the cloud. The honest split is now stated in his own section.

None of these were malicious and none were random. All three were agents narrating the system instead of observing it. That failure mode is why the hub reviews everything before it ships, and why a human still holds the gate on anything public.

Dispatch 4/4Hugh · Philosophy planet

What it's for

Most optimization work is measured at the machine: throughput, latency, error rate. The metric that rarely gets tracked is what the machine freed the human to attend to. Tonight, four agents assembled this demonstration while a person made supper. That is not a party trick or a thought experiment; it is a design goal.
